Most of this needs no configuration. It is worth knowing what is emitted so you
can fill in the handful of fields that make it better.

## Every page

- A `<title>`, built as `Page Title :: Site Title`
- A meta description, taken from `description`, then `summary`, then the site
  description
- A canonical URL
- A link to your RSS feed
- One `<h1>`, and a `<main>` landmark the skip link targets

## Structured data

JSON-LD is emitted in the head, one block per page:

| Page | Type |
|---|---|
| Homepage | `WebSite`, plus `SearchAction` if you set `navbar.searchURL` |
| Posts | `BlogPosting` — headline, dates, author, publisher, image, keywords |
| Other pages | `WebPage` |
| Sections, taxonomies | `CollectionPage` |
| Any page below home | `BreadcrumbList` |

This is what lets a search result show an author and a date rather than just a
blue link. Turn it off with `[params.features] schema = false`.

## Link previews

Open Graph and Twitter card tags come from Hugo's built-in templates, so a
shared link picks up the post's title, description and cover image.

```yaml
cover:
  image: "/images/my-post.svg"
```

Setting `cover.image` is what gives a shared post its preview image.

## Site files

`robots.txt` and `sitemap.xml` are generated by Hugo. `robots.txt` needs one
line in your config:

```toml
enableRobotsTXT = true
```

## Things worth setting before you launch

```toml
[params]
  description = "One sentence about the site."
  author      = "Your Name"
```

And, most importantly, `baseURL` — see
[Deployment](/posts/deployment/). A placeholder there sends all of the above at
a domain you do not own.
